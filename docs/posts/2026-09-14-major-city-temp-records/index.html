Every day, pulls the most recent officially reported daily high temperature for the 50 most populous US cities, compares each one against that station’s own all-time high for that calendar day, and maps how close every city came to (or how far past) its record.

What this page does

Every time this page is rendered (including the scheduled daily rebuild — see the note at the bottom), it:

  1. Takes a fixed list of the 50 most populous US cities (a standard proxy for “most influential” — see the caveats section for why population, not some other ranking, was used).
  2. For each city, finds the nearest long-running weather station and pulls its most recently reported daily maximum temperature — in practice, this is usually “yesterday,” but station reporting lags by a few days at some sites, so the actual date used is shown per city.
  3. Compares that reading against the all-time record high for that station on that same calendar day (the warmest that station has ever recorded on that specific month/day, across every other year in its digitized daily record).
  4. Replays the same comparison for every day since January 2020 across all resolved cities, and keeps a running tally — broken out by year — of how many city-days set/tied a record or came within 3 degrees.
  5. Plots all 50 cities on a US map, colored by how each city’s most recent reading compared to its record.
Important

This is a live, self-refreshing page, not a one-time snapshot. There’s no server behind it — it’s a static site. At render time, this code re-fetches real station data and recomputes everything below. What you see is only as fresh as the last render (daily, via cron).

HIST_START = datetime(1885, 1, 1)   # predates nearly every US first-order station's digitized record

                                     # airport station if the closest site turns out to be short-lived

MIN_RECORD_YEARS = 20               # a station with less history than this can't give a credible "record" --
                                     # a "record" based on only a handful of years is misleading, not just imprecise
MAX_STALENESS_DAYS = 21             # how far back we'll accept a station's "most recent" reading --
                                     # set generously (3 weeks) on purpose: the long-running official
                                     # stations that make the best *record* sources tend to also have
                                     # the slowest final QC/reporting lag (observed ~8-9 days for
                                     # several), so a tight staleness cutoff was silently disqualifying
                                     # exactly the stations this page most wants to use, in favor of

def diff_bucket(diff_f):
    """Map a (actual - record) °F difference onto the DIFF_BINS color ramp."""
    for upper, color, label in DIFF_BINS:
        if diff_f <= upper:
            return color, label
    return DIFF_BINS[-1][1], DIFF_BINS[-1][2]


TALLY_CATEGORIES = ["Above record", "At record (tied)", "Within 3°F of record"]


def tally_category(diff_f):
    """
    Mutually-exclusive running-tally buckets (distinct from the finer
    DIFF_BINS used for map coloring): a city-day counts toward exactly one
    of these three.

    if diff_f > 1:
        return "Above record"
    if diff_f >= -1:
        return "At record (tied)"
    if diff_f >= -3:
        return "Within 3°F of record"
    return None  # not close enough to tally

2. Pull each station’s full daily-max-temperature history

Fetched in parallel — each station’s history is an independent network call, and there’s no reason to wait for one before starting the next.

Code 
def fetch_station_tmax(station_id):
    ts = meteostat.daily(station_id, HIST_START, FETCH_END, parameters=[Parameter.TMAX])
    df = ts.fetch(units=UnitSystem.IMPERIAL)
    if df is None or df.empty:
        return None
    return df["tmax"].dropna()


# Fetch every candidate for every city (not just the nearest one) so the
# best-populated station can be picked rather than just the closest one
# that clears a minimum bar. This matters: nearby() returns candidates by
# *distance*, and the physically closest site is sometimes a short-lived or
# sparsely-reporting station (e.g. a personal/community site) sitting right
# next to a much longer-running official airport station a few km further
# out. Picking "nearest that passes" over "most complete overall" was
# initially producing "records" built on a couple sparse decades instead of
# a station's full, well-populated history -- a bug caught by manually
# comparing candidate station row counts for a test city, not something
# any of the individual per-station checks below would have caught on
# their own since a sparse station can still individually look "valid."
all_candidate_ids = sorted({sid for ids in city_candidates.values() for sid in ids})
station_series = {}
with ThreadPoolExecutor(max_workers=N_WORKERS) as pool:
    futures = {pool.submit(fetch_station_tmax, sid): sid for sid in all_candidate_ids}
    for future in futures:
        sid = futures[future]
        station_series[sid] = run_stage(f"station {sid} (fetch)", future.result)


def resolve_city(label, candidates):
    """
    Among this city's already-fetched candidate stations, pick whichever
    has the most actual years of history (not just whichever is nearest)
    and is recent enough to stand in for "yesterday." Returns None (city
    dropped, reason logged) if none qualify.
    """
    reasons = []
    scored = []
    for station_id in candidates:
        series = station_series.get(station_id)
        if series is None or series.empty:
            reasons.append(f"{station_id}: no data returned")
            continue

        n_years = series.index.year.nunique()
        if n_years < MIN_RECORD_YEARS:
            reasons.append(f"{station_id}: only {n_years} year(s) of history")
            continue

        latest_available = series.index.max().date()
        if (TARGET_DATE - latest_available).days > MAX_STALENESS_DAYS:
            reasons.append(
                f"{station_id}: most recent reading ({latest_available}) is more "
                f"than {MAX_STALENESS_DAYS} days before target date {TARGET_DATE}"
            )
            continue

        scored.append((n_years, station_id, series))

    if not scored:
        raise RuntimeError(f"No usable candidate station for {label}: " + "; ".join(reasons))

    # Most years of history wins, not nearest distance.
    n_years, station_id, series = max(scored, key=lambda t: t[0])

    date_used = TARGET_DATE if TARGET_DATE in series.index.date else series.index.max().date()
    actual_f = float(series.loc[series.index.date == date_used].iloc[0])

    same_calendar_day = series[
        (series.index.month == date_used.month) & (series.index.day == date_used.day)
    ]
    same_calendar_day = same_calendar_day[same_calendar_day.index.date != date_used]
    if same_calendar_day.empty:
        raise RuntimeError(
            f"No usable candidate station for {label}: best candidate {station_id} has "
            f"no other year's data for {date_used.month}/{date_used.day}"
        )

    return {
        "station": station_id, "date_used": date_used, "actual_f": actual_f,
        "record_f": float(same_calendar_day.max()), "n_years_compared": len(same_calendar_day),
        "series": series,  # kept for the back-calculated daily tally below -- avoids re-fetching
    }


results = {}
with ThreadPoolExecutor(max_workers=N_WORKERS) as pool:
    futures = {
        pool.submit(resolve_city, label, city_candidates[label]): label
        for name, state, lat, lon in CITIES
        for label in [f"{name}, {state}"]
    }
    for future in futures:
        label = futures[future]
        result = run_stage(label, future.result)
        if result is not None:
            results[label] = {**result, "diff_f": round(result["actual_f"] - result["record_f"], 1)}

4. Back-calculated running tally since 2020

A single day’s snapshot is a small sample — most cities aren’t near their record on any given day. To get a real sense of how often major US cities are running hot relative to their own history, this section replays the same comparison for every day since datetime.date(2020, 1, 1) for each of the 50 resolved cities (using the station histories already pulled above — no extra fetching needed), and keeps a cumulative tally across all of it.

The one thing that has to change for a multi-year replay: “the record” can’t be a fixed number looked up once, because it should only reflect what was actually the record at the time — a September day in 2021 should be judged against the record as it stood coming into 2021, not against a hotter day that happened to occur in 2023. So for each station and each calendar day, this uses an expanding, backward-looking record: the highest reading ever seen on that calendar day in any earlier year. If a year sets a new record, that becomes the bar every later year is compared against.

def expanding_daily_comparison(series):
    """
    For one station's full daily-tmax series, return a DataFrame (one row
    per date) with each day's reading compared against the expanding,
    backward-looking record for that calendar day -- i.e. the max reading
    ever seen on that month/day in a *strictly earlier* year.

    Rows where fewer than MIN_PRIOR_SAMPLES earlier years exist for that
    calendar day are dropped, not just rows with zero prior years. A
    station can pass the overall MIN_RECORD_YEARS bar and still have a
    calendar day's "record" resting on only a handful of early
    observations -- comparing against a record that immature makes it
    trivially easy to "beat," which would inflate every tally below with
    noise rather than genuine extremes.
    """
    df = series.rename("actual_f").to_frame()
    df["month"] = df.index.month
    df["day"] = df.index.day
    grouped = df.groupby(["month", "day"])["actual_f"]
    df["prior_record_f"] = grouped.transform(lambda s: s.expanding().max().shift(1))
    df["prior_n"] = grouped.transform(lambda s: s.expanding().count().shift(1))
    df = df[df["prior_n"] >= MIN_PRIOR_SAMPLES]
    df["diff_f"] = (df["actual_f"] - df["prior_record_f"]).round(1)
    return df[["actual_f", "prior_record_f", "diff_f"]]

Method notes & caveats

  • “50 most influential cities” = 50 most populous cities. Population (~2023-2024 Census estimates) is used as a standard, reproducible proxy for “influential” — there’s no single agreed-upon ranking for the latter, and population is the one that’s citable and doesn’t change based on opinion.
  • Data source: Meteostat, which aggregates NOAA/NWS (and other) station daily summaries. Station histories vary in length — some (e.g. long-running first-order airports) go back 80+ years; others considerably less. The “Years compared” column in the results table shows exactly how many other years’ worth of data each city’s “record” is actually based on, so a thin record is visible rather than hidden. This is each station’s own digitized daily record, not necessarily an official NWS all-time record for that city (which may rely on a longer or differently-sourced period of record).
  • Reporting lag: some stations’ daily summaries aren’t finalized for several days. This page targets “yesterday” (datetime.date(2026, 9, 14)) but falls back to a station’s own most recent reading (within 21 days) when “yesterday” isn’t available yet — the “Date used” column shows exactly which date each city’s row reflects, since they aren’t guaranteed to all be the same day.
  • Station choice picks the most complete candidate, not the nearest one. Up to 5 candidates within 120 km are fetched for each city, and whichever has the most actual years of history is used — not whichever is physically closest. This was a deliberate fix after an initial version picked the nearest station unconditionally (as long as it cleared MIN_RECORD_YEARS), which for at least one test city turned out to be a nearby short/sparsely-reporting site instead of a much longer-running official airport station a few km further out — that produced “records” resting on a couple sparse decades rather than a station’s real history. Picking by completeness instead of distance is a cheap, reliable proxy for station quality here.
  • A calendar day’s record also needs a minimum sample size of its own (MIN_PRIOR_SAMPLES = 15 earlier years), applied in the back-calculated tally in the next section. A station can pass the overall history-length bar while a specific month/day within it still has very few prior observations early in the record, making that day’s “record” trivially easy to beat — this floor keeps those thin spots out of the tally instead of counting them as genuine extremes.
  • Tally vs. map categories are deliberately different granularities. The running tally uses three mutually-exclusive buckets (above record: more than 1°F over; tied: within 1°F either way; within 3°F: 1-3°F under) as requested. The map uses a finer 7-color ramp over the full range of possible differences, so a city that’s, say, 25°F under its record is still visually distinguishable from one that’s 5°F under — the tally only tracks the “close calls.”
  • The back-calculated tally uses an expanding, backward-looking record, not the same “all other years” record as the single-day snapshot above. For the single day this page targets (yesterday), those two definitions happen to agree, since there’s no later data to leak in. But replaying years of history the naive way — comparing every day against the max over all years, including ones after it — would let a hot day in 2024 count as “the record” a 2020 reading is judged against, which reverses cause and effect. Instead, each day is compared only to the highest reading ever seen on that calendar day in a strictly earlier year, so a new record set in one year correctly raises the bar for every year after it, and never for years before it.
  • Why 2020, and why 3°F: 2020 was chosen as a round, recent starting point with enough span to show a year-over-year pattern rather than just one data point; there’s nothing special about that year beyond that. The “within” threshold was tightened from an initial 5°F to 3°F to keep that bucket meaning “genuinely close,” not just “somewhere in the neighborhood.”
  • DEBUG_RAISE = False: a city that fails at any stage (no usable station, insufficient history, stale data) is dropped, with the reason logged as an HTML comment in the page source, rather than taking down the whole page. Flip it to True temporarily to get a full traceback while debugging a specific city.
  • Large-request guard disabled on purpose: Meteostat blocks any single daily-data request spanning more than 30 years by default. That’s turned off here (meteostat.config.block_large_requests = False) deliberately, since computing an honest “record for this calendar day” requires each station’s entire digitized history, not just the last 30 years.
  • Station fetches run in parallel (ThreadPoolExecutor, up to 10 at once) since each is an independent network call to Meteostat’s bulk data — this cut the total render time for all 50 cities from roughly the sum of each individual fetch (which can be tens of seconds each) down to a couple of minutes.

## What this page does

Every time this page is rendered (including the scheduled daily rebuild —
see the note at the bottom), it:

1. Takes a fixed list of the **50 most populous US cities** (a standard proxy
   for "most influential" — see the caveats section for why population,
   not some other ranking, was used).
2. For each city, finds the **nearest long-running weather station** and
   pulls its **most recently reported daily maximum temperature** — in
   practice, this is usually "yesterday," but station reporting lags by a
   few days at some sites, so the actual date used is shown per city.
3. Compares that reading against the **all-time record high for that
   station on that same calendar day** (the warmest that station has ever
   recorded on that specific month/day, across every other year in its
   digitized daily record).
4. Replays the same comparison for **every day since January 2020** across
   all resolved cities, and keeps a **running tally** — broken out by year —
   of how many city-days set/tied a record or came within 3 degrees.
5. Plots all 50 cities on a **US map**, colored by how each city's most
   recent reading compared to its record.

```{python}
def resolve_city(label, candidates):
    """
    Among this city's already-fetched candidate stations, pick whichever
    has the most actual years of history (not just whichever is nearest)
    and is recent enough to stand in for "yesterday." Returns None (city
    dropped, reason logged) if none qualify.
    """
    reasons = []
    scored = []
    for station_id in candidates:
        series = station_series.get(station_id)
        if series is None or series.empty:
            reasons.append(f"{station_id}: no data returned")
            continue

        n_years = series.index.year.nunique()
        if n_years < MIN_RECORD_YEARS:
            reasons.append(f"{station_id}: only {n_years} year(s) of history")
            continue

        latest_available = series.index.max().date()
        if (TARGET_DATE - latest_available).days > MAX_STALENESS_DAYS:
            reasons.append(
                f"{station_id}: most recent reading ({latest_available}) is more "
                f"than {MAX_STALENESS_DAYS} days before target date {TARGET_DATE}"
            )
            continue

        scored.append((n_years, station_id, series))

    if not scored:
        raise RuntimeError(f"No usable candidate station for {label}: " + "; ".join(reasons))

    # Most years of history wins, not nearest distance.
    n_years, station_id, series = max(scored, key=lambda t: t[0])

    date_used = TARGET_DATE if TARGET_DATE in series.index.date else series.index.max().date()
    actual_f = float(series.loc[series.index.date == date_used].iloc[0])

    same_calendar_day = series[
        (series.index.month == date_used.month) & (series.index.day == date_used.day)
    ]
    same_calendar_day = same_calendar_day[same_calendar_day.index.date != date_used]
    if same_calendar_day.empty:
        raise RuntimeError(
            f"No usable candidate station for {label}: best candidate {station_id} has "
            f"no other year's data for {date_used.month}/{date_used.day}"
        )

    return {
        "station": station_id, "date_used": date_used, "actual_f": actual_f,
        "record_f": float(same_calendar_day.max()), "n_years_compared": len(same_calendar_day),
        "series": series,  # kept for the back-calculated daily tally below -- avoids re-fetching
    }


results = {}
with ThreadPoolExecutor(max_workers=N_WORKERS) as pool:
    futures = {
        pool.submit(resolve_city, label, city_candidates[label]): label
        for name, state, lat, lon in CITIES
        for label in [f"{name}, {state}"]
    }
    for future in futures:
        label = futures[future]
        result = run_stage(label, future.result)
        if result is not None:
            results[label] = {**result, "diff_f": round(result["actual_f"] - result["record_f"], 1)}

print(f"Resolved {len(results)} / {len(CITIES)} cities.")
if failures:
    print(f"{len(failures)} city/stage combination(s) failed -- see HTML source comments for details.")
```

## 4. Back-calculated running tally since 2020

A single day's snapshot is a small sample — most cities aren't near their
record on any given day. To get a real sense of *how often* major US cities
are running hot relative to their own history, this section replays the same
comparison for **every day since `{python} TALLY_START_DATE`** for each of
the `{python} len(results)` resolved cities (using the station histories
already pulled above — no extra fetching needed), and keeps a cumulative
tally across all of it.

The one thing that has to change for a multi-year replay: "the record" can't
be a fixed number looked up once, because it should only reflect what was
*actually the record at the time* — a September day in 2021 should be judged
against the record as it stood coming into 2021, not against a hotter day
that happened to occur in 2023. So for each station and each calendar day,
this uses an **expanding, backward-looking record**: the highest reading
ever seen on that calendar day in any *earlier* year. If a year sets a new
record, that becomes the bar every later year is compared against.

```{python}
#| label: historical-tally

def expanding_daily_comparison(series):
    """
    For one station's full daily-tmax series, return a DataFrame (one row
    per date) with each day's reading compared against the expanding,
    backward-looking record for that calendar day -- i.e. the max reading
    ever seen on that month/day in a *strictly earlier* year.

    Rows where fewer than MIN_PRIOR_SAMPLES earlier years exist for that
    calendar day are dropped, not just rows with zero prior years. A
    station can pass the overall MIN_RECORD_YEARS bar and still have a
    calendar day's "record" resting on only a handful of early
    observations -- comparing against a record that immature makes it
    trivially easy to "beat," which would inflate every tally below with
    noise rather than genuine extremes.
    """
    df = series.rename("actual_f").to_frame()
    df["month"] = df.index.month
    df["day"] = df.index.day
    grouped = df.groupby(["month", "day"])["actual_f"]
    df["prior_record_f"] = grouped.transform(lambda s: s.expanding().max().shift(1))
    df["prior_n"] = grouped.transform(lambda s: s.expanding().count().shift(1))
    df = df[df["prior_n"] >= MIN_PRIOR_SAMPLES]
    df["diff_f"] = (df["actual_f"] - df["prior_record_f"]).round(1)
    return df[["actual_f", "prior_record_f", "diff_f"]]


daily_frames = []
```

## Method notes & caveats

- **"50 most influential cities" = 50 most populous cities.** Population
  (~2023-2024 Census estimates) is used as a standard, reproducible proxy
  for "influential" — there's no single agreed-upon ranking for the latter,
  and population is the one that's citable and doesn't change based on
  opinion.
- **Data source**: [Meteostat](https://meteostat.net/), which aggregates
  NOAA/NWS (and other) station daily summaries. Station histories vary in
  length — some (e.g. long-running first-order airports) go back 80+ years;
  others considerably less. The **"Years compared"** column in the results
  table shows exactly how many other years' worth of data each city's
  "record" is actually based on, so a thin record is visible rather than
  hidden. This is each **station's own digitized daily record**, not
  necessarily an official NWS all-time record for that city (which may rely
  on a longer or differently-sourced period of record).
- **Reporting lag**: some stations' daily summaries aren't finalized for
  several days. This page targets "yesterday" (`{python} TARGET_DATE`) but
  falls back to a station's own most recent reading (within
  `{python} MAX_STALENESS_DAYS` days) when "yesterday" isn't available yet
  — the **"Date used"** column shows exactly which date each city's row
  reflects, since they aren't guaranteed to all be the same day.
- **Station choice picks the most complete candidate, not the nearest one.**
  Up to `{python} N_CANDIDATE_STATIONS` candidates within
  `{python} STATION_SEARCH_RADIUS_M // 1000` km are fetched for each city,
  and whichever has the most actual years of history is used — *not*
  whichever is physically closest. This was a deliberate fix after an
  initial version picked the nearest station unconditionally (as long as it
  cleared `MIN_RECORD_YEARS`), which for at least one test city turned out
  to be a nearby short/sparsely-reporting site instead of a much
  longer-running official airport station a few km further out — that
  produced "records" resting on a couple sparse decades rather than a
  station's real history. Picking by completeness instead of distance is a
  cheap, reliable proxy for station quality here.
- **A calendar day's record also needs a minimum sample size of its own**
  (`MIN_PRIOR_SAMPLES` = `{python} MIN_PRIOR_SAMPLES` earlier years), applied
  in the back-calculated tally in the next section. A station can pass the
  overall history-length bar while a specific month/day within it still has
  very few prior observations early in the record, making that day's
  "record" trivially easy to beat — this floor keeps those thin spots out of
  the tally instead of counting them as genuine extremes.
- **Tally vs. map categories are deliberately different granularities.**
  The running tally uses three mutually-exclusive buckets (above record:
  more than 1°F over; tied: within 1°F either way; within 3°F: 1-3°F under)
  as requested. The map uses a finer 7-color ramp over the full range of
  possible differences, so a city that's, say, 25°F under its record is
  still visually distinguishable from one that's 5°F under — the tally
  only tracks the "close calls."
- **The back-calculated tally uses an *expanding*, backward-looking record,
  not the same "all other years" record as the single-day snapshot above.**
  For the single day this page targets (`yesterday`), those two definitions
  happen to agree, since there's no later data to leak in. But replaying
  years of history the naive way — comparing every day against the max over
  *all* years, including ones after it — would let a hot day in 2024 count
  as "the record" a 2020 reading is judged against, which reverses cause
  and effect. Instead, each day is compared only to the highest reading
  ever seen on that calendar day in a **strictly earlier year**, so a new
  record set in one year correctly raises the bar for every year after it,
  and never for years before it.
- **Why 2020, and why 3°F**: `{python} TALLY_START_DATE.year` was chosen as
  a round, recent starting point with enough span to show a year-over-year
  pattern rather than just one data point; there's nothing special about
  that year beyond that. The "within" threshold was tightened from an
  initial 5°F to 3°F to keep that bucket meaning "genuinely close," not just
  "somewhere in the neighborhood."
- **`DEBUG_RAISE = False`**: a city that fails at any stage (no usable
  station, insufficient history, stale data) is dropped, with the reason
  logged as an HTML comment in the page source, rather than taking down the
  whole page. Flip it to `True` temporarily to get a full traceback while
  debugging a specific city.
- **Large-request guard disabled on purpose**: Meteostat blocks any single
  daily-data request spanning more than 30 years by default. That's turned
  off here (`meteostat.config.block_large_requests = False`) deliberately,
  since computing an honest "record for this calendar day" requires each
  station's *entire* digitized history, not just the last 30 years.
- **Station fetches run in parallel** (`ThreadPoolExecutor`, up to
  `{python} N_WORKERS` at once) since each is an independent network call to
  Meteostat's bulk data — this cut the total render time for all 50 cities
  from roughly the sum of each individual fetch (which can be tens of
  seconds each) down to a couple of minutes.
